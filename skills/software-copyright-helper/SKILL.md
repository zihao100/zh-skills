# software-copyright-helper - 软件著作权材料整理助手

## 核心目标

帮助开发者和团队依据中国版权保护中心（CPCC）最新申请规范，自动化提取与排版符合要求的源代码文档、撰写系统设计说明书/用户手册，并整理申请表核心参数。

## 触发场景

- 用户需要申报中国软件著作权（例如："帮我整理软著材料"、"准备软著源代码"、"写软著操作手册"）
- 需要按规范提取项目的前后 30 页核心代码
- 需要梳理软著申请表所需的软硬件环境、开发完成时间与技术特性

---

## 软著材料三大核心要素与合规要求

### 1. 源程序代码文档规范
- **页数要求**：
  - 总体少于 60 页（约 3000 行）的，提供**全部源代码**。
  - 总体大于 60 页的，提供**前连续 30 页 + 后连续 30 页**（共 60 页）。
- **单页要求**：
  - 每页不少于 **50 行**（通常排版设置为 55~60 行，单倍行距，9~10 号等宽字体，如 Consolas / Courier New）。
  - 第 60 页的最后一行必须为**程序结束代码**（如闭合大括号 `}` 或模块出口）。
- **内容合规**：
  - **严禁包含开源第三方库原生代码**（如 React、Spring 原生源码、node_modules 等）。
  - 去除连续空行，避免大段无关注释（尤其是带有他人署名、其他商业机构名称或开源许可证头文件的注释）。
  - 保持代码连续性，具备可读性与完整结构。
- **页眉页脚**：
  - 页眉：必须包含**软件全称、简称及版本号**（与申请表必须 100% 字符一致）。
  - 页脚：标注当前页码与总页数（第 1 页 至 第 60 页）。

### 2. 用户操作手册 / 设计说明书规范
- 文档篇幅一般不少于 15 页。
- 必须包含**真实系统截图**（图文并茂），截图内的软件名称、版本号需与申请表一致。
- 目录层级清晰，结构建议如下：
  1. 软件概述与系统定位
  2. 运行环境配置（硬件、操作系统、数据库、中间件及浏览器要求）
  3. 系统核心功能架构
  4. 业务功能详细操作指南（分模块、带配图流程说明）
  5. 异常处理与常见问题

### 3. 申请表关键元数据梳理
- **软件全称**：品牌/公司名 + 核心功能 + 系统/平台/软件（如：`星云分布式任务调度管理系统`）。
- **软件简称**：可选（如：`星云调度`）。
- **版本号**：格式通常为 `V1.0` 或 `V1.0.0`。
- **开发完成日期与首次发表日期**：逻辑需自洽（发表日期不得早于完成日期）。
- **主要功能与技术特点**：采用客观技术陈述，字数在 200~500 字。

## 工作流与操作步骤

### 第一步：分析项目技术栈与文件结构
- 扫描代码仓库，确定主技术栈（如 Java、TypeScript、Go、Python）。
- 识别项目自主研发的核心业务模块目录（排除依赖库与构建物）。

### 第二步：提取与规整源代码
1. **筛选自主代码**：优先选取控制器（Controller）、服务层（Service）、核心算法与数据模型文件。
2. **规范化处理**：
   - 清理多余空行；
   - 过滤带有外部公司版权的头部注释；
   - 保证代码行排版紧凑。
3. **分段拼接**：生成前 30 页（约 1650 行）与后 30 页（约 1650 行）的纯净文本。

### 第三步：生成设计说明书或操作手册大纲
根据项目功能路由或接口清单，输出详细的图文排版大纲，标注每一处建议放置截图的位置。

### 第四步：输出自检报告与填表指引
生成软著申报参数清单，方便直接复制至中国版权保护中心申报后台。

- **版本号**: V1.0
- **软件分类**: 应用软件 / 基础软件

- **运行硬件环境**: 2核 4GB 内存以上服务器/PC
- **开发软件环境**: macOS / Linux / Windows 11, VS Code, Python 3.11, Docker
- **运行软件环境**: Linux Ubuntu 22.04 LTS / CentOS 7+, Docker 24.0+
- **编程语言**: Python 3.11, Vue 3, TypeScript
- **代码总行数**: 约 [填写真实统计行数] 行
- **软件主要功能说明**:
  [概括系统的3-5个核心功能模块，客观说明输入、处理与输出，突出业务逻辑完整性]
- **技术特点说明**:
  [突出系统的架构选型、并发能力、数据安全性、模块解耦等技术优势]

## 质量自检清单

- [ ] 提取代码中是否存在外部第三方商业许可证标识（必须彻底清理）
- [ ] 提取的前后代码行数是否满足每页 >= 50 行的密度标准
- [ ] 说明书/操作手册中的系统截图是否打码了敏感凭证或隐私数据
- [ ] 软件全称在代码页眉、手册封面与申请表中保持一字不差
