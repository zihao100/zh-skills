# changelog-zh - 中文版本更新日志生成器

## 核心目标

基于 Git 提交历史（`git log`）或 PR 列表，提取并重构版本变更，过滤内部杂音，输出符合 [Keep a Changelog](https://keepachangelog.com/) 规范的中文版本更新日志。

## 触发场景

- 项目准备打 Tag 发布新版本时生成 `CHANGELOG.md` 或 Release Notes
- 撰写面向终端用户、客户或产品团队的中文版本升级公告
- 整理两版本之间的差异与迁移指南（Migration Guide）

---

## 日志分类标准 (Keep a Changelog 中文映射)

每次版本发布的内容按以下标准分类（按影响重要度自上而下）：

1. **💥 破坏性更新 (Breaking Changes)**：不向下兼容的 API、数据结构或配置改动
2. **🚀 新增功能 (Added)**：面向用户或调用的新特性、新页面、新命令
3. **⚡ 性能与优化 (Changed / Optimized)**：现有功能的逻辑改进、性能提升、体验重构
4. **🐛 缺陷修复 (Fixed)**：修复的问题、异常崩溃与安全隐患
5. **⚠️ 弃用说明 (Deprecated)**：计划在后续版本移除的旧功能
6. **🗑️ 移除功能 (Removed)**：已在本次版本中彻底移除的功能
7. **🔒 安全修复 (Security)**：涉及漏洞修补、依赖安全更新的改进

## 工作流与操作步骤

### 第一步：获取版本间的 Git 变更
```bash
# 获取自上一个 Tag 以来的所有提交
git log $(git describe --tags --abbrev=0)..HEAD --oneline

# 或指定两版本范围
git log v1.2.0..v1.3.0 --pretty=format:"%h - %s (%an)"
```

### 第二步：过滤与去噪（关键步骤）
- **剔除内部琐碎提交**：如 `fix typo`, `update readme`, `format code`, `merge branch 'main'`, `bump version`。
- **合并同类改动**：将针对同一功能或缺陷的多次修补合并为一条完整表述。

### 第三步：站在用户视角重写描述
- **避免直接搬运 Git 提交原文**：技术细节应转化为用户感受到的实际价值或解决的场景。
  - 差：`feat: add redis cache to get_user_detail`
  - 好：`⚡ 优化：重构用户资料查询链路，首屏加载速度提升 60%`

### 第四步：格式化输出
按照统一的 Markdown 模板输出，并更新根目录下的 `CHANGELOG.md`。

## 更新日志 Markdown 结构模板

```markdown
# 更新日志 (Changelog)

所有针对本项目的重大变更都将记录在此文件中。
版本号严格遵循 [语义化版本 2.0.0 (Semantic Versioning)](https://semver.org/lang/zh-CN/)。

---

## [1.3.0] - 2026-10-29

### 💥 破坏性更新
- **API 接口路径规范化**: 原 `/v1/getOrder` 接口已彻底废弃，统一迁移至 `/v1/orders`。请前端及第三方调用方在升级前更新 SDK。

### 🚀 新增功能
- **深色模式支持**: 全站支持基于系统偏好自动切换暗黑模式与明亮模式，可在个人设置中手动锁定偏好。
- **导出报表功能**: 订单管理中心支持导出近 90 天的 Excel 与 CSV 交易流水。

### ⚡ 优化改进
- **高并发下单优化**: 引入基于 Redis 的分布式排队机制，秒杀场景下的系统并发吞吐量提升 3 倍。
- **页面交互调优**: 优化移动端下拉刷新的流畅度，修复部分机型掉帧现象。

### 🐛 缺陷修复
- **支付超时退款异常**: 修复在极端弱网环境下支付回调重试时，退款状态未及时更新的偶发 Bug。
- **表单校验穿透**: 修复收货人手机号在输入特殊字符时未触发格式校验的问题。

### 🔒 安全更新
- 升级 `jsonwebtoken` 依赖至 9.0.2 版本，修补潜在的弱密钥解析安全漏洞。
```

## 质量自检清单

- [ ] 版本号是否遵循 SemVer（主版本号.次版本号.修订号）
- [ ] 发布日期格式是否规范（YYYY-MM-DD）
- [ ] 是否过滤掉了开发过程中的临时 commit（如 "wip", "update"）
- [ ] 破坏性变更是否有显著的标注与升级迁移指引
- [ ] 描述语言是否通俗精准，中英文排版留有空格
