# tech-blog-zh - 中文技术博客与深度文章写作

## 核心目标

帮助开发者撰写逻辑严密、深入浅出、具备实战价值的高质量中文技术博客与架构文章。告别枯燥的 API 堆砌与空洞套话，打造具备高阅读体验与传播度的技术内容。

## 触发场景

- 用户需要撰写技术博客、技术教程或原理剖析（例如："帮我写一篇关于 Redis 缓存击穿的深度文章"）
- 将某个复杂项目或攻坚成果整理为对外分享的沉淀总结
- 优化现有技术文章的排版、行文叙事与图表设计

## 写作原则与风格规范

### 1. 杜绝 AI 套话与机翻腔
- **严禁使用陈词滥调**：如“在当今快节奏的数字时代”、“正如我们所知”、“显而易见的是”、“总而言之，这是一把双刃剑”。
- **开门见山**：从开发者切身痛点、线上真实踩坑事故或反直觉的技术现象切入。
- **直击本质**：不仅讲“怎么用”，更要剖析“为什么这样设计”以及底层的底层运行机制与权衡（Trade-offs）。

### 2. 中文技术排版标准（盘古之白与专有名词）
- **中英文空格**：汉字与英文单词、阿拉伯数字之间必须保留一个半角空格。
  - 正确：`使用 Redis 7.0 的 Stream 实现分布式消息队列`
  - 错误：`使用Redis7.0的Stream实现分布式消息队列`
- **专有名词规范大小写**：
  - 正确：`JavaScript`, `TypeScript`, `Node.js`, `MySQL`, `PostgreSQL`, `Kubernetes`, `Docker`, `Git`, `macOS`, `iOS`
  - 错误：`javascript`, `Typescript`, `nodejs`, `mysql`, `k8s`（标题中尽量规范写为 Kubernetes）
- **标点符号**：中文语境内严格使用全角标点符号（，。！？；：“”），代码块及英文缩写内使用半角。

### 3. 图解优先
- 对复杂的交互流、状态转换或系统架构，必须配合 Mermaid 流程图/时序图，使抽象概念一目了然。

## 经典技术文章黄金架构（五步法）

```
1. 痛点引子 (Hook & Problem)
   ↳ 真实业务场景 / 线上偶发 Bug / 性能遇到天花板

2. 底层原理剖析 (Deep Dive)
   ↳ 核心机制解密 + Mermaid 架构/时序图 + 内存/状态演进

3. 优雅实现方案 (Implementation)
   ↳ 精简可运行的关键代码 + 核心参数拆解

4. 生产避坑与权衡 (Pitfalls & Trade-offs)
   ↳ 极端边界场景 + 性能调优 + 降级容灾方案

5. 总结与延伸思考 (Takeaway & Discussion)
   ↳ 知识结构化脑图 + 开放性思考题
```

## 工作流与操作步骤

### 第一步：锁定受众与核心卖点
- 明确目标读者定位（初学者、一线研发、架构师）。
- 提炼本文的独家价值：相比官方文档，本文提供了哪些独到的实战经验或原理拆解？

### 第二步：搭建文章骨架与逻辑线
- 设计层层递进的章节标题（避免使用平淡无奇的“一、介绍 二、使用 三、总结”）。
- 设计核心流程的 Mermaid 图。

### 第三步：填充正文与关键代码
- 代码片段保持精炼，突出核心逻辑，并在关键行增加行内中文注释。
- 使用生活化或形象的比喻解释晦涩机制（如将写时复制比作共享图书笔记）。

### 第四步：润色排版与自检
- 检查中英文空格、专有名词、代码块语法高亮标签。

## 示例片段：痛点引入与图表

```markdown
# 为什么你的 Redis 读写分离依然撑不住大促流量？

深夜两点，监控大屏突发尖刺报警，主库 CPU 飙升至 99%，从库却“悠闲地”处于低负载状态。
运维同学的第一反应通常是：“我们不是做了读写分离吗？为什么流量还是把主库打垮了？”

问题的根源往往不在于主从同步自身，而在于客户端对只读连接池的路由策略与长事务穿透。

### 数据流向全景

\`\`\`mermaid
sequenceDiagram
    autonumber
    actor Client as 业务客户端
    participant Proxy as 路由中间件
    participant Master as Redis Master (写主库)
    participant Replica as Redis Replica (读从库)

    Client->>Proxy: 执行读请求 (SELECT)
    alt 处于事务上下文中
        Proxy->>Master: 强制穿透至主库 (避免脏读)
    else 普通查询
        Proxy->>Replica: 轮询路由至从节点
    end
\`\`\`
```
