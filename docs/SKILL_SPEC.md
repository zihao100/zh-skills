# zh-skills 技能开发规范与最佳实践 (Skill Specification)

本文档定义了 `zh-skills` 技能仓库的统一设计规范与开发标准。所有收录的技能均需遵循此规范，以保证跨平台（Antigravity、Claude Code、Cursor 等）的最高兼容性、触发准确率与 Token 利用效率。

---

## 1. 核心设计哲学

### 1.1 渐进式披露 (Progressive Disclosure)
Agent Skill 的上下文加载分为三层：
1. **元数据层 (Metadata)**：`name` 与 `description`。启动时常驻在 Agent 系统提示词中（约 100 词以内），由模型判断是否需要激活。
2. **正文层 (SKILL.md Body)**：当技能被触发时整篇载入上下文。**理想篇幅建议控制在 500 行以内**。
3. **扩展资源层 (Bundled Resources)**：存放于 `references/`、`scripts/` 或 `assets/` 目录。仅在模型需要深入查阅或执行确定性任务时按需读取，不占用默认上下文。

### 1.2 明确且具召唤力的描述 (Pushy Description)
当前大多数 LLM 存在“技能欠触发 (Undertriggering)”倾向——即在用户遇到对应场景时未主动调用技能。
- **反例**：“用于协助编写中文文章。”（过于模糊，模型几乎不会触发）
- **正例**：“撰写高质量、深度、引人入胜的中文技术博客与架构剖析文章。涵盖生动的痛点引入、原理剖析、图文并茂的架构图、避坑指南与规范的中文排版。适用于技术分享、公众号、掘金、知乎等场景。”（包含关键词、适用上下文与触发场景）

### 1.3 确定性逻辑优先下沉到脚本
- 如果某项任务可以通过一行 Shell 脚本或 Python 脚本 100% 确定性完成（如代码行数过滤、正则替换、文件打包），**请写成脚本置于 `scripts/`**，并在 `SKILL.md` 中指引 Agent 执行该脚本，而不是让 LLM 消耗数千 Token 自行计算。

---

## 2. 目录结构规范

每个技能必须是一个独立的文件夹，位于 `skills/<skill-name>/` 下：

```text
skills/<skill-name>/
├── SKILL.md             # [必填] 技能主入口定义文件
├── scripts/             # [可选] 可执行脚本 (Python/Bash)
│   └── helper.py
├── references/          # [可选] 大篇幅参考资料、数据字典、行业规范
│   └── detailed-spec.md
└── assets/              # [可选] 输出模板、图片、字体等静态资源
    └── template.docx
```

---

## 3. YAML Frontmatter 格式

`SKILL.md` 文件头部必须包含标准的 YAML Frontmatter，使用 `---` 分界：

```markdown
---
name: skill-name
description: 详细描述技能的功能、适用场景、中文触发词。必须清晰指引模型何时调用本技能。
---
```

### 字段说明
- `name` (必填): 字符串，**必须与所在文件夹名称保持完全一致**，使用全小写中划线（kebab-case）。
- `description` (必填): 字符串，长度建议在 50~200 字之间。包含功能定位与触发关键词。

---

## 4. SKILL.md 正文标准结构

正文内容需逻辑清晰，推荐包含以下模块：

1. **核心目标**：用 1~2 句话阐明本技能要交付的最终价值。
2. **触发场景**：列出触发该技能的典型用户语句与使用场景。
3. **工作流与操作步骤 (Workflow)**：
   - 第一步：上下文与前置条件校验；
   - 第二步：核心处理或分析逻辑；
   - 第三步：结构化交付与结果验证。
4. **交付模板 / 示例**：展示给用户看得清楚的输出样例（如表格、Diff、Markdown 结构）。
5. **质量自检清单 (Checklist)**：提供 Markdown checkbox，方便 Agent 在生成最终回复前自我审计。

---

## 5. 语言排版规范（中文标准）

- **盘古之白**：中文与英文、数字之间必须留有一个半角空格。
- **全角标点**：中文正文必须使用标准中文全角标点符号（，。！？；：“”）。
- **专有名词**：严格遵循行业标准官方大小写（如 `TypeScript`, `Node.js`, `Docker`, `PostgreSQL` 等）。
- **杜绝陈腐套话**：严禁空洞、假大空的 AI 开场白与总结句。
